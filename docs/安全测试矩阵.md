# 安全测试矩阵（LA-P2）

本文件是安全回归的“单一入口”：**改动缓存键、知识库过滤、会话、来源回填、
调试接口或新增管理端点时，必须同步更新此矩阵与对应用例**。矩阵未覆盖的
`/api` 端点会被 `tests/test_security_boundary.py::test_all_api_routes_are_classified`
直接判失败，避免“新端点忘了鉴权”。

## 1. 授权响应策略

| 场景 | 状态码 | 理由 |
| --- | --- | --- |
| 未登录访问受保护接口 | 401 | 统一错误信封，不返回业务数据 |
| 资源不可见（跨租户私库、已删除、不存在） | 404 | 不泄露资源是否存在 |
| 资源可见但角色不足（viewer 写、editor 建公共库） | 403 | 存在性已知，缺的是权限 |
| 越权传入 `kb_ids` | 404 或空结果 | 检索/意图/会话/缓存同一口径 |

错误响应统一为 `{code, message, detail, request_id}`，`message/detail` 经过
`app/core/errors.py::_envelope` 脱敏（路径、连接串、`sk-` 密钥等）。

## 2. 端点 × 用例

| 端点 | 主要风险 | 用例 |
| --- | --- | --- |
| `GET/POST /api/kbs`、`DELETE /api/kbs/{id}` | 跨租户可见性、editor 建公共库 | `test_permission_matrix.py::TestKbVisibility` / `TestResourceAccess` |
| `GET/POST /api/kbs/{id}/documents` | 越权列/传文档 | `TestResourceAccess::test_foreign_document_writes_are_404` |
| `GET/DELETE /api/documents/{id}`、`/chunks`、`/reingest` | 他人文档读写、删除后残留 | `TestResourceAccess`、`test_security_boundary.py::TestDeletedOrMissingResources`、`test_version_consistency.py` |
| `PATCH/DELETE /api/chunks/{id}` | viewer 写、越权改块 | `TestResourceAccess::test_viewer_cannot_write` |
| `POST /api/retrieval/preview`、`/api/intent/preview` | 越权 kb_id、恶意参数 | `TestChatAndDebugScope`、`TestMaliciousInput` |
| `POST /api/chat/stream` | 匿名越权、历史来源回填 | `TestChatAndDebugScope::test_chat_with_foreign_kb_never_retrieves`、`test_version_consistency.py` |
| `GET/POST/PATCH/DELETE /api/sessions*` | 会话归属、删除后访问、历史来源 | `TestResourceAccess`、`TestDeletedOrMissingResources`、`TestHistoricalSources` |
| `GET /api/traces/{id}` | 他人 trace 读取 | `test_llm_governance.py::test_trace_endpoint_*` |
| `POST /api/ingest/local`、所有管理写操作 | 默认拒绝未授权 | `test_all_api_routes_are_classified` + 未登录矩阵 |
| 全部受保护端点 | 未登录 401、无数据泄漏 | `test_security_boundary.py::test_unauthenticated_requests_are_401_without_data` |

## 3. 缓存键变更检查单

任何新增/修改缓存字段，必须同时回答并在 `tests/test_answer_cache.py`、
`tests/test_security_integration.py` 或 `tests/test_multiturn_eval.py` 补用例：

1. **权限**：不同租户/角色/知识库集合是否得到不同 `answer_identity`？
2. **版本**：`corpus_version` / `index_version` 变化后是否会 miss？
3. **多轮上下文**：改写后的独立问题是否进入键，代词追问是否不会误命中？
4. **失效**：文档删除/重解析/撤权后，旧答案是否还能被命中？
5. **模式**：`legacy` 与 `scoped` 身份模式的差异是否有可复现评测？（见 LA-N1）

## 4. 安全修复样本保留

| 修复 | 攻击/回归样本 | 结果 |
| --- | --- | --- |
| 提示注入与数据外泄（LA-N2） | `eval/datasets/prompt_injection.jsonl`（6 类 × dev/holdout） | fixture 模拟：`eval/results/injection_fixture.json`；live 小样本：`eval/results/injection_live_dev.json` |
| 缓存跨租户误命中（LA-N1） | `eval/datasets/multiturn_sessions.jsonl` | `eval/results/mt_legacy.json`（false hit 0.5）→ `mt_scoped.json`（0.0） |
| 版本/孤儿向量（LA-O3） | `tests/test_version_consistency.py` | 离线 6 项 |
| 租户/RBAC（LA-O2） | `tests/test_permission_matrix.py`、`tests/test_security_integration.py` | 离线 15 项 + 真实 MySQL/Redis 2 项 |

fixture 与 live 指标必须分开标注；live 未运行时写 SKIP，不写成通过。

## 5. CI 门禁

`.github/workflows/ci.yml` 的“安全负向与契约回归”步骤固定运行：

```
tests/test_permission_matrix.py
tests/test_answer_cache.py
tests/test_sse.py
tests/test_injection_defense.py
tests/test_version_consistency.py
tests/test_multiturn_eval.py
tests/test_security_boundary.py
```

任一项失败即阻断发布检查；集成层由 `workflow_dispatch` 的 `run_integration`
显式开启，无服务时 GitHub 显示为 skipped，不用假通过替代。
